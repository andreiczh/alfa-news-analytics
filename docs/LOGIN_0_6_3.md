# Вход и тестовый аккаунт · 0.6.3

25 октября 2026 года. Рамка изменения: экран входа/регистрации и создание изолированного аккаунта для проверки. Правила финансовой аналитики v6.2 не менялись.

## Изменение

В прежнем HTML были `login-shell` и `intro-panel`, а CSS определял `login-layout` и `intro`. Поэтому вводная часть и форма располагались последовательно и занимали несколько экранов. Новые страницы используют собственные согласованные классы `account-*`: одна карточка до 432 px, логотип сверху, кнопка и переход между входом/регистрацией. На узком экране карточка занимает доступную ширину; длинная регистрация прокручивается обычным способом. Обновляемый CSS имеет версию в URL.

## Операторское создание аккаунта

`python -m alfa_agent.provision_demo` принимает только через переменную `ALFA_PROVISION_ACCOUNT` JSON с полями `login`, `password_hash`, `full_name`, `company`, `job_title`. Разрешён формат PBKDF2-SHA256, 600 000 итераций, индивидуальная соль 16 байт. Plaintext-пароль не нужен команде; ни пароль, ни хеш не публикуются в документации, HTML или логе команды.

Команду запускает оператор, HTTP-метода для неё нет. Она создаёт отдельные аккаунт и пространство в одной транзакции. Совпадение компании не даёт доступ к другому пространству. Повторение разрешено только для ранее созданного этой командой аккаунта с тем же хешем и профилем; иной существующий аккаунт, отключённая запись или изменённый пароль не перезаписываются. При отсутствии переменной команда ничего не делает. После создания переменную и временную команду запуска убирают из конфигурации Render. Политика обычной регистрации и смены пароля — от 12 символов — сохранена.

## Критическая проверка

1. **Сильная версия решения:** короткая форма входа доступна сразу, тестовый аккаунт работает обычным способом через общую проверку пароля и сессии.
2. **Что подтверждено:** локально 15 браузерных проверок: обе страницы на пяти размерах 1440×900, 1280×720, 768×1024, 390×844, 320×568; отклонение неверного пароля, вход, отзыв сессии при выходе, повторный вход в то же пространство, проверка допустимых символов логина. Горизонтального переполнения и ошибок JS нет. Снимки просмотрены вручную. 278 обычных тестов и 9 интеграционных PostgreSQL прошли, включая конкурентное создание одного тестового аккаунта без дублей. Исправлен HTML pattern для совместимости с Unicode Sets в Chromium: недопустимый логин отклоняется и браузером, и сервером.
3. **Риски:** общий тестовый аккаунт не подтверждает личность человека; любой его пользователь видит его материалы. Для личных данных следует создать свой аккаунт. Большой системный шрифт, реальная экранная клавиатура и особенности Safari требуют отдельной аппаратной проверки.
4. **Предпосылки:** CSS доступен и страница открыта с обычным масштабом; приложение использует действующую PostgreSQL, а не временную SQLite.
5. **Живая проверка:** Render 0.6.3, runtime `3e8a22bb20831ea9791681cf3d98c25a8c2f7410`, deployment `dep-dbf3gc8473hc73bnevlg`. 16 браузерных проверок, ошибок JS 0: вход, компания/роль CFO, повторный вход в то же пространство, отзыв сессии, запрет чужого пространства с тем же работодателем, обе страницы на пяти размерах. Все три опубликованных файла HTML/CSS совпали с исходниками побайтово. Временная переменная создания аккаунта удалена, обычная команда запуска восстановлена; прежние секреты сохранены. [Протокол](../validation-login-063.json), [CI/Docker/Compose](https://github.com/andreiczh/alfa-news-analytics/actions/runs/40215037075).
6. **Уверенность:** 95% в исправлении воспроизведённой проблемы компоновки и рабочем тестовом входе; локальные и облачные проверки выполнены. Это не переоценка всей системы как промышленно готовой. Аппаратная проверка Safari/клавиатуры остаётся отдельной задачей.
