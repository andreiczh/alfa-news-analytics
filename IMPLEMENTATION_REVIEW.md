# Проверка версии 0.2 — 23 октября 2026

Исторический отчёт. Текущая версия — **0.3.2**; актуальные возможности и ограничения: [аудит кейса](docs/CASE_COMPLIANCE_REVIEW.md), [проверки](validation-report-v3.json), [Render](DEPLOYMENT.md). Указанные ниже незавершённые задачи относятся к моменту проверки 0.2.

## 1. Steelman

Запрос: перенести продуктовую логику Miro в рабочий интерфейс, использовать реальные данные кейса и автоматически формировать профиль из файлов компании. Сильная проверяемая версия решения — сквозной путь от выбора клиента/загрузки до источников, контролируемого сценария и пяти ролевых выводов.

## 2. Strengths

- **[Проверено]** Miro прочитана через публичную доску. Включены карточка главного события с причиной показа и приоритетом проверки, пять ролей, пробелы профиля, избранное, настройки быстрого доступа и постоянная точка входа на главной. [Происхождение и текст](docs/miro-source.json).
- **[Проверено]** Все три CSV полностью проиндексированы: 85 525 строк профилей / 85 514 ID, 1 380 585 платёжных строк, 12 514 физических связей. `CLIENT` — 41 968 ID. Признаки наблюдаемого платёжного среза и физические связи доступны агенту с формулами/источниками; они не становятся доказательством поставок, контроля или кредитной экспозиции.
- **[Проверено]** Рабочая загрузка PDF/сканов, DOCX, PPTX, XLSX, CSV и текста; ограниченные локальные парсеры, очередь, разрешённая VL-модель для OCR и текстовая модель для извлечения. У каждого принятого числового поля — исходная численная запись, цитата и проверенная единица/масштаб.
- **[Проверено]** Противоречия не усредняются. Файл можно исключить/вернуть; старые снимки/оригиналы сохраняются. Чужой файл и исключённый документ не подмешиваются в активный контекст. Идемпотентность не меняет старый результат при новых загрузках.
- **[Проверено]** Живой разбор `U_100110`: `run_04efacff8b8545c581eb`, PARTIAL, 5 LLM calls / 2 tools. Все три CSV представлены в снимке; 5 признаков вычислены по наблюдаемому срезу. Плавающая ставка/денежный эффект не выдуманы.
- **[Проверено]** Живой путь по явно синтетическим файлам TXT + скан PDF: 9 принятых показателей из текста, 4 из скана; два разрешённых model IDs; затем `run_bcf66bb4e3564e4f9970`, SUCCEEDED, 6 calls / 3 tools, 1 корректировка после проверки. Версия профиля 4, пять ролей; 800 млн × −1 п.п. × 90/365 = −1 972 602,74 руб. условного изменения расхода. Предыдущие прогоны сохранены отдельно и не выдаются за текущие.
- **[Проверено]** Автотесты, browser QA и ручной осмотр desktop/mobile отражены в `validation-report-v2.json`. Контракт полного CSV-профиля расширен с сохранением ограничения размера; устранены старые фоновые процессы и добавлены lock/parent watchdog с настоящей проверкой завершения дочернего процесса.

## 3. Weaknesses & risks

| Приоритет | Ограничение | Следствие |
|---|---|---|
| P1 | Один датированный тип события — ставка; свободный researcher/чат и новые новости не реализованы | Нельзя объявлять устойчивость к любым новым событиям, полное покрытие Miro или всех 12 критериев |
| P1 | Банк — три выбранных утверждения страницы 1 одного PDF, pending_human_review | Полный корпус из девяти PDF и полнота позиции банка не подтверждены |
| P1 | Текстовое/визуальное извлечение может ошибаться, несмотря на точные цитаты и кодовые проверки | Нужна независимая проверка на настоящих документах компаний; synthetic E2E не измеряет precision/recall |
| P1 | Рублёвые единицы/периоды CSV и часть бизнес-семантики известны только из пересказа вебинара | Числа не используются как подтверждённый текущий оборот, прибыль, валютная позиция или денежная долговая экспозиция |
| P1 | Один локальный demo principal; настоящая SSO/полномочия/мультитенантность банка отсутствуют | Показан контролируемый прототип с привязкой документов к компании, не банковская интеграция |
| P1 | Ключ/общий остаток бюджета контролируется также другими участниками команды | Считаются attempts/usage, действует circuit на ошибку провайдера; рублёвый остаток не выдумывается |
| P2 | Строгое согласование не выбирает автоматически период/новейший документ; нет полноценного редактора полей | Пользователь проверяет кандидаты и исключает неактуальный документ; полезные данные могут остаться неизвестными |
| P2 | OCR ограничен PDF; изображения DOCX/PPTX и неподписанные графики не оцифрованы | Покрытие файла явно показывается в замечаниях, полнота визуальных презентаций не обещается |
| P2 | Docker отсутствует; нет закреплённого GitHub-релиза и независимого quality benchmark | Подготовленная конфигурация не равна проверенному контейнеру и полной готовности к сдаче |
| P2 | Второй LLM-проход использует ту же текстовую модель | Это дополнительная автоматическая проверка, не независимое экспертное заключение |

Отдельно исправленные реальные сбои: старый лимит 20 evidence при полном профиле; шесть осиротевших worker старых запусков, один из которых забрал новый запрос; пропущенные raw_value для дней/долей. Первые два не вызвали LLM на соответствующих ошибочных запусках. Неполные числовые кандидаты не публиковались. Изменения подтверждены регрессией и последующим живым путём.

## 4. Hidden assumptions

- Пользователь корректно привязал материалы к компании. Имя из файла не доказывает соответствие обезличенному ID; система не устанавливает его автоматически.
- Оставленные активными документы относятся к нужному решению/периоду. Различные периоды не сводятся к одному значению без пользовательского согласования.
- Сценарий предполагает полный перенос договорной ставки в начале горизонта, постоянный остаток и заданную базу дней. Хедж, комиссии, налоги и график погашения неизвестны.
- API организаторов сохранит текущие model IDs/протокол. Успех отдельных вызовов не задаёт SLA, тариф или общий benchmark.

## 5. What to verify

- [Высокая уверенность] Кодовые пути/интерфейс — отчёт тестов, browser-validation-v2.json, SQLite trace, HTML/JSON результатов.
- [Требует первичного ответа] Семантика/периоды CSV, коллизия U_428697, финансовые единицы и границы использования внешних материалов.
- [Требует человека] Все банковские claims и выборка извлечений из настоящих клиентских отчётов/презентаций; источники, даты, единицы и принадлежность компании.
- [Следующий этап] Новые новости, независимая разметка relevance/unsupported rate, полный банковский корпус, настоящая авторизация, Docker build, GitHub и комплект конкурсной сдачи.

## 6. Confidence

**90% в описанном локальном сценарии и проверенных ветках.** Это не оценка финансовой точности на всех реальных документах, полноты Miro/ТЗ или шансов на победу. Синтетический профиль проверки явно отделён от обезличенных данных организаторов.
