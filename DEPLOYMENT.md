Демо: https://alfa-business-pulse.onrender.com. Отдельный сервис `srv-dbdphesipgvc739mcm80`, Render Free, Frankfurt, один API и один worker. Другие сервисы аккаунта не изменяются.

Точная опубликованная версия и облачная проверка фиксируются после развёртывания в `validation-report-v3.json`. Локальные проверки: 92 теста, Ruff, синтаксис JavaScript, установка по lock-файлу, 15 браузерных проверок и живой разбор «Альфа-Банк, CFO» (PARTIAL, 3 вызова модели, 2 инструмента, 0 изменений плана).

## Конфигурация

Build: `pip install --require-hashes -r requirements.lock && python -m alfa_agent build-case-index`. Start: `python -m alfa_agent serve`. Порт задаёт Render. Индекс CSV строится до запуска и открывается на чтение; гонка индексации исправлена в предыдущем релизе.

Секреты: `ALFA_LLM_API_KEY`, `ALFA_ACCESS_PASSWORD`, `ALFA_SESSION_SECRET`. Общий пароль не изменялся; отдельный секрет подписи добавлен на сервис без публикации значения. `.env*` и файл с паролем исключены из Git. Сессии старого формата потребуют нового входа с ФИ/компанией/должностью.

Состояние: `/tmp/alfa-state`, ephemeral demo. Новые файлы и история теряются после простоя/перезапуска; исходные примеры восстанавливаются. При стабильных секретах подписанная сессия может восстановить пустое личное пространство, но не потерянные файлы.

## Проверка и откат

Перед публикацией: тесты, синтаксис, проверка источников, скан секретов, commit/push в приватный репозиторий. Обновление выполняется вручную на конкретный commit; auto-deploy выключен.

После публикации: health/version и worker, вход, личная компания, документы, свежий вопрос, проверка, роли, уточнение, экспорт, мобильный экран и изоляция сотрудников. Сбой старта, неработающий вход или нарушение изоляции — повод остановить проверку и вернуться к проверенной версии.
