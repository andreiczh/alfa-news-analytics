## Доступ и ограничения Free

Пароль команды сохранён локально в `render-access.txt`, источник — игнорируемый `.env.render`; оба файла имеют права 0600. В Render пароль и LLM-ключ переданы как секретные переменные окружения. Их значений нет в Git, отчётах, фронтенде или опубликованных ответах.

Это общая рабочая область команды за паролем, не банковская SSO и не изоляция разных клиентов. Кука входа — Secure/HttpOnly/SameSite, действует 12 часов. API дополнительно требует токен страницы и проверяет Origin/Host.

**Пользователь выбрал бесплатное демо на хакатон.** Render останавливает Free после 15 минут без входящих запросов. Новые загруженные файлы, созданные компании, разборы и избранное теряются при остановке/перезапуске. При запуске возвращается исходный проверенный снимок с двумя готовыми разборами и двумя явно синтетическими документами. Предупреждение отображается в интерфейсе; важные результаты следует экспортировать. [Официальные ограничения](https://render.com/docs/free).

Для постоянного сохранения предусмотрен `ALFA_STATE_DIR` на диске платного сервиса. Оплата в аккаунте не подключена; платные ресурсы не создавались.

## Запуск и обновление

Build: `pip install --require-hashes -r requirements.lock && python -m alfa_agent build-case-index`.

Start: `python -m alfa_agent serve`; один API и один дочерний worker, один инстанс сервиса, порт из `PORT`. Health: `/api/health`, проверяет также состояние worker.

Индекс создаётся при сборке и открывается на чтение обоими процессами. Перед использованием хеши сверяются с CSV. Это устраняет конкурирующую индексацию при запуске на ограниченном CPU. Первый вариант запуска выявил блокировку SQLite; в проверенную версию вошли исправление и регрессионный тест. Соединения индекса закрываются явно.

После изменения кода: проверки → commit/push в приватный репозиторий → ручной deploy конкретного commit через Render. `deploy/render.py` предназначен для первоначального создания сервиса; при существующем сервисе он не выполняет обновление. Для возврата к проверенной версии можно развернуть указанный выше commit. Версия `119ecea` не является рабочей облачной точкой отката.

Dockerfile обновлён, но локальная Docker-сборка по-прежнему не проверялась. Успешно проверен нативный Python runtime Render.

## Critical review

1. **Steelman.** Команда получает HTTPS-ссылку на полноценный существующий прототип с данными и живым агентом без настройки своего компьютера.
2. **Strengths.** Сценарий выполнен именно на Render: новый файл, профиль, вызовы API, проверка, пять ролей и экспорт. Репозиторий приватный, секреты отделены, исходные демо восстанавливаются.
3. **Weaknesses & risks.** Free теряет новые данные после перезапуска и имеет холодный старт. Командный пароль не заменяет клиентскую авторизацию. Проверен один датированный сценарий, не все новости и не весь банковский корпус.
4. **Hidden assumptions.** Работа зависит от доступности Render, организаторского API и остатка общего дневного лимита команды. Источники остаются ограниченными исходным сценарием.
5. **What to verify.** Перед защитой открыть ссылку заранее, проверить бюджет API и скачать важные результаты. Новые типы событий, OCR нового скана именно в облаке, нагрузка и независимая финансовая оценка этим прогоном не проверены.
6. **Confidence: 95%** в проверенном размещении и вертикальном сценарии; это не оценка полноты конкурсного решения или качества произвольной аналитики.
