# Пульс бизнеса: прототип 0.2

Рабочий путь: **событие о ставке → профиль из CSV и документов компании → аналитика Альфа-Банка → условный расчёт → проверка → CFO / казначей / CEO / COO / CCO**.

Интерфейс и логика переработаны по ТЗ и текстовым блокам [доски Miro](https://miro.com/app/board/uXjVEY6IJiQ=/?share_link_id=975023695519). Название доски осталось «CJM: ведение пациента», её текущие блоки относятся к новостной аналитике Альфа-Бизнеса. [Сохранённый текст и происхождение](docs/miro-source.json). «Пульс бизнеса» — рабочее название интерфейса, не утверждённый бренд команды.

## Открыть и запустить

Для Render подготовлен [Blueprint](render.yaml) бесплатного демо. Python-сервер слушает `PORT` на `0.0.0.0`; API и один worker запускаются вместе. Доступ команды защищён паролем, LLM-ключ передаётся только через секрет Render. Это общий контур команды, не банковская SSO и не разделение доступа между клиентами.

**Бесплатный хостинг:** после простоя/перезапуска новые файлы, компании и история теряются. При новом запуске восстанавливается проверенный исходный снимок с готовыми разборами и явно синтетическими тестовыми документами. Важные результаты необходимо экспортировать. Это ограничение согласовано пользователем для демо на хакатон; [условия Render](https://render.com/docs/free). Для постоянного хранения предусмотрен `ALFA_STATE_DIR` на подключённом диске платного сервиса; код не перезаписывает существующее состояние.

На этой машине окружение и локальный ключ настроены. Адрес: **http://127.0.0.1:8765**. Для последующих запусков — двойной клик по `Запустить агента.command`; окно запуска должно оставаться открытым.

```sh
uv sync --frozen
uv run alfa-agent serve
```

Нужны Python 3.12 и uv. Worker — отдельный процесс; один worker на папку состояния, с завершением после остановки родительского приложения. Можно запустить API и worker раздельно, как в `compose.yaml`.

Ключ читается из `ALFA_LLM_API_KEY` или `.env.local` с правами 0600. Он не включается в промпты, результаты, UI, Docker-образ или логи. По прямому разрешению пользователя применяется ранее выданный ключ; его значение в документации отсутствует.

## Пользовательский путь

1. В верхней панели выбрать клиента из кейса: поиск по ID, отрасли или региону. По умолчанию показываются `CLIENT` — 41 968 уникальных ID. Это интерпретация аудитории из пересказа вебинара, отдельно от авторизации банка.
2. На главной постоянно доступен «Пульс бизнеса»: событие, причина отбора, приоритет проверки, позиция банка и переход к разбору. Приоритет `! / !! / !!!` обозначает наличие оснований для проверки, не вероятность или подтверждённую величину ущерба.
3. Открыть «Профиль компании»: источник, единицы, исходные цитаты и недостающие/несогласованные поля. Кредитный флаг не превращается в плавающий долг; депозитный сценарий отличается от долгового.
4. Для собственной компании нажать «Добавить свою компанию», затем загрузить документы. Можно также явно привязать файлы к выбранному ID кейса; система не устанавливает эту связь по названию автоматически.
5. Подтвердить выбранную компанию и загрузить файлы. Очередь выполняет чтение → OCR при необходимости → извлечение → проверку цитат/чисел/единиц → согласование кандидатов → новую версию профиля. Численный кандидат без исходной численной записи вызывает исправление ответа модели, а не тихое заполнение числа.
6. После обработки запустить разбор. Открыть пять ролей, основания, формулу сценария, ограничения. При известном плавающем типе и неизвестном остатке агент сначала проверяет материалы, затем задаёт вопрос. Неизвестный тип ставки не заменяется плавающим.
7. Документ можно исключить из будущих разборов и вернуть обратно. Оригинал и прошлые снимки сохраняются. Это позволяет согласовать противоречащие файлы без изменения уже опубликованных выводов. Повторное извлечение запускается отдельным действием и расходует API.
8. Работают избранное, настройка кнопок быстрого доступа, история, обратная связь, экспорт и адаптация к узкому экрану. Ответ на уточнение сохраняется в конкретном разборе; постоянный профиль новых запусков собирается из активных документов. Роль меняет представление; в прототипе она выбирается вручную. Это моделируемый контур, не настоящая банковская SSO.

## Реальные данные кейса

Приложение индексирует три исходных CSV в `ALFA_STATE_DIR/case.sqlite3` (локально `var/case.sqlite3`), сохраняя строки, ID и SHA-256. Источники читаются из упакованного `data/case/`, исходного `../sources/data/` либо `ALFA_CASE_DATA_DIR`; исходные файлы не меняются. Набор распространяется только в приватном репозитории и за командным входом.

| Источник | Полный объём | Использование |
|---|---:|---|
| `df_Uid_data_hack.csv` | 85 525 строк / 85 514 уникальных ID | Профиль, ОКВЭД, продукты, география регистрации, группа, пропуски и конфликты |
| `df_Uid_payment_hack.csv` | 1 380 585 строк | Направленные агрегаты среза, контрагенты и доли, отдельно переводы себе; признаки с формулами и источником попадают в контекст агента |
| `df_Fid_Uid_link_hack.csv` | 12 514 строк | Наблюдаемые связи и число ID физлиц; владение, контроль, права и должность не выводятся |

Повторяющиеся пары/строки сохранены. Неизвестные контрагенты не удаляются inner join. Коллизия `U_428697` остаётся несогласованной. Финансовые единицы и периоды CSV в словаре ТЗ не установлены; рубли/2025 и период платежей до 31.10.2026 известны из вторичного пересказа и требуют подтверждения. По ним не строится рублёвый эффект, прибыль, доля рынка или полная концентрация бизнеса.

Событие — реальное решение ЦБ **11 сентября 2026**, сохранение **14%**. Это датированный пример, не лента последних новостей. Банк — реальный PDF той же даты: включены **три выбранных утверждения страницы 1 из 4**, `pending_human_review`. Все девять PDF и полная разметка банковского корпуса ещё не подключены.

## Загрузка документов

Поддерживаются PDF с текстом и сканы, DOCX, PPTX, XLSX, CSV, TXT, MD. Лимиты: 15 МБ на файл; 20 файлов / 100 МБ на компанию; 100 000 символов текста; PDF до 40 страниц, до 8 страниц без текстового слоя; презентации до 60 слайдов. Превышение даёт явную ошибку, не незаметную обрезку.

PDF разбирается локально; страницы без текста распознаёт разрешённая **`qwen/qwen3-vl-30b-a3b-instruct`**. Текстовые сведения извлекает **`qwen/qwen3.6-35b-a3b`**. Числа нормализуются только при явных единицах; исходная запись, цитата и фрагмент обязательны. Период остаётся неизвестным, если он не указан. Изображения DOCX/PPTX и неподписанные графики не оцифровываются; это видно в замечаниях к файлу. Формулы и макросы не исполняются, внешние ссылки из файлов не открываются.

Извлекаются деятельность, бизнес-модель, рынки/международная деятельность, продукты, указанные конкуренты, стратегия/тактика и поддерживаемые финансовые показатели. Это сведения источника, не автоматически доказанные факты. Несовпадающие значения и периоды не усредняются и не разрешаются выбором удобного документа.

Оригиналы хранятся в `var/uploads/`, права 0600. SHA-дедупликация действует внутри компании. Документ другой компании недоступен через её маршрут/снимок. Локальный demo principal допускает выбор профилей кейса; production SSO и банковские полномочия не реализованы.

## Агент и состояние

Собственная Python-машина состояний: `HYDRATE → PLAN ↔ TOOL_EXEC → ANALYZE → VERIFY ↔ исправление/поиск → PROJECT → PUBLISH`. Есть `WAITING_INPUT`, `DEFERRED_BUDGET`, `FAILED`, `CANCELLED`, checkpoint/CAS и журнал. OpenClaw/LangGraph/LangChain runtime не используются. Production-заглушек LLM нет; test double находится только в `tests/`.

- `case_data.py` — полный импорт CSV и воспроизводимые признаки наблюдаемого среза.
- `workspace.py` — привязка файлов, очередь, кандидаты/конфликты, версии, исключение/возврат документов, неизменяемые снимки каждого запуска.
- `document_parser.py`, `ingestion.py` — ограниченный парсер, OCR и извлечение с проверкой источников; задания переживают перезапуск. Неоднозначный потерянный запрос не считается бесплатным и не повторяется скрыто.
- `corpus.py` — SQLite FTS5 и проверка компании, доступности и точного состава снимка. Исключённый или более новый документ не подмешивается в старый разбор.
- `engine.py`, `tools.py` — планирование, контролируемый dispatch, уточнение, расчёт и переходы. Схема planner сужается до разрешённых инструментов текущего пробела.
- `role_rules.py`, `assembly.py`, `roles.py` — предметные условные правила. LLM выбирает источник/механизм/действие; код копирует исходные факты и рассчитывает числа. Это первый канал влияния ставки, не универсальный генератор экономических рекомендаций.
- `verification.py` — ссылки, авторство, время, единицы, числа, вклад банка и отдельный LLM-verifier. Ошибки `unsupported / wrong owner / time / number / contradiction` блокируют публикацию.
- `api.py`, `static/` — интерфейс, загрузка, история, избранное, источники и feedback; Host/Origin/session checks, вывод пользовательских данных через textContent.

Для долга **800 млн руб.**, условного шага **−1 п.п.**, постоянного остатка и базы **90/365** изменение расхода = **−1 972 602,74 руб.** Это гипотетический шаг договорной ставки, не экономия от сохранения ключевой ставки, не прогноз банка и не обещание. Тип ставки, остаток и условия должны иметь основания. Существенность относительно прибыли остаётся неизвестной без согласованного знаменателя/порога.

## API и пределы

Endpoint организаторов: `https://changellenge.up.railway.app/v1`. Шесть разрешённых IDs фиксируются кодом. Текстовый и VL-маршруты проверяются отдельными живыми заданиями; нативные tools, strict response_format и streaming приложение не требует. `reasoning.enabled=false` — принятый шлюзом параметр, не доказательство устройства proxy или тарифа.

**500 ₽/сутки на командный ключ**, сброс **03:00 МСК**. Рублёвый баланс и тарифы неизвестны. Записываются attempts/usage; ограничение провайдера общее для всех участников и моделей. При budget error оба вида заданий откладываются до сброса, без смены модели для обхода лимита.

На разбор: ≤12 LLM attempts с учётом исправлений JSON, ≤8 tools, ≤2 replans, 300 секунд активной работы, HTTP timeout 60 секунд. На один файл ≤24 attempts, до одного исправления структуры на пакет. Это ограничения прототипа, не SLA. Worker и анализ используют общий слот выполнения; отдельный lock не допускает несколько фоновых worker одной папки.

## Проверки

```sh
uv run pytest -q
uv run ruff check src tests
```

Автотесты не расходуют API. Покрываются CSV/пропуски/коллизии/неизвестные контрагенты, документный путь, единицы и цитаты, чужие файлы, конфликты/исключение/снимки, агентные переходы, API/лимиты и завершение worker после родителя. Синтетические файлы для проверки загрузки: `data/test_documents/`; они явно помечены и не привязываются к реальному ID из кейса.

Живые run IDs, модельные вызовы, browser QA, скриншоты и оставшиеся ограничения фиксируются в `validation-report-v2.json` и `IMPLEMENTATION_REVIEW.md`. Автоматическая проверка не равна независимой финансовой экспертизе; успешный запуск не является benchmark качества на новых новостях.

## Docker и воспроизводимость

```sh
docker compose up --build
```

Два процесса с общим volume состояния; CSV монтируются из `../sources/data` только для чтения, порт — на 127.0.0.1. Нужны три исходных CSV по ссылкам организаторов либо настройка каталога в compose. `uv.lock` и `requirements.lock` фиксируют версии/хеши. Секреты и новые пользовательские файлы в образ не включаются. В `deploy/seed` находятся только исходный проверенный снимок и явно синтетические QA-документы; SHA-256 проверяется перед первым восстановлением.

**Docker в этой среде отсутствует; сборка контейнера не проверена.** Проверен локальный Python-запуск.

## Границы текущего этапа

Ещё не реализованы: новые новости/новостной parser, полный банковский корпус/OCR девяти PDF, универсальный мировой/отраслевой/конкурентный ресерч, свободный аналитический чат, прогнозирование вне явных сценариев, банковская SSO/push/production hosting и независимый quality benchmark. Эти идеи из Miro/ТЗ не выдаются за готовые функции. Здесь работает персонализация одного датированного события по реальному набору и загруженным документам.
