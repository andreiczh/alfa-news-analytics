# Пульс бизнеса · 0.4.0

Персональная новостная аналитика для руководителей: **сотрудник → компания и документы → свой вопрос → источники → проверенный условный вывод → уточнение**.

[Открыть демо на Render](https://alfa-business-pulse.onrender.com). Используйте прежний пароль команды из локального `render-access.txt`. На входе укажите имя и фамилию, компанию и должность. API-ключ в браузер не передаётся.

[Аудит требований и границ реализации](docs/CASE_COMPLIANCE_REVIEW.md) · [Свежие новости и ранжирование](docs/NEWS_SEARCH_REVIEW.md) · [Реестр источников](docs/SOURCE_REGISTER.md) · [Размещение и откат](DEPLOYMENT.md).

## Пользовательский сценарий

1. Войти с готовым паролем команды, ФИ, компанией и должностью. Создаётся личное рабочее пространство. Одно название компании не объединяет документы разных сотрудников. Это демонстрационный вход, не подтверждение трудоустройства или банковская SSO.
2. В «Моей компании» описать бизнес, при необходимости указать сайт и загрузить документы. Поддерживаются PDF, DOCX, PPTX, XLSX, CSV, TXT, MD: 15 МБ на файл, 20 файлов и 100 МБ на компанию. Файлы привязаны к выбранной компании; извлечённые признаки имеют цитаты и статусы. Изображения внутри Office-файлов не распознаются; сканированные PDF ограничены 8 страницами.
3. На «Обзоре» автоматически открывается «Что важно сейчас»: прямые ленты ЦБ/РБК и новостной поиск по публичному названию компании. Выбрать роль и период 7/30/90 дней, раскрыть причину приоритета и нажать «Разобрать для CFO». Дата публикации, источник и факт чтения статьи показаны отдельно. Подборка обновляется при открытом интерфейсе по истечении 15 минут; «Обновить» запускает проверку вручную с ограничением частоты. Это не push-мониторинг при закрытом приложении.
4. Либо задать собственный вопрос в «Исследовании», добавить текст новой новости и до трёх HTTPS-ссылок. Открытый поиск отправляет только публичное название компании; внутренние документы, ФИ, вопрос и показатели не входят в запрос поиска. Их анализ выполняет разрешённая модель через API организаторов. Для обезличенной компании доступны общие ленты без поискового запроса по ID.
5. Агент собирает контекст компании и банковские материалы, выбирает дальнейший поиск, формирует вывод и проверяет его. Для цифр и цитат действует отдельная проверка кодом. Выбранная новость загружается из серверного снимка, её текст нельзя заменить клиентским заголовком. Обязательная связь интерпретации с выбранным событием проверяется кодом. PARTIAL означает проверенный вывод с ограничениями, а не доказанную полноту исследования.
6. Посмотреть срез для CFO, казначея, CEO, COO или CCO; раскрыть первоисточники; задать уточнение; сохранить в избранное; скачать Markdown-отчёт; оставить отзыв. Уточнение использует исходный снимок профиля и источники родительского исследования. Новый отдельный вопрос использует текущий профиль.

В «Сменить компанию» доступны собственные пространства, обезличенные компании CSV и явно синтетические примеры. Примеры и компании кейса доступны на чтение. Реальное имя работодателя **не сопоставляется автоматически** с анонимным ID. Расчётный сценарий ставки для корпоративной компании сохранён отдельно. Банку он не применяется: нужны ALM, структура активов/обязательств, сроки переоценки и депозитная бета.

## Источники и ограничения

- Три оригинальных CSV организаторов индексируются при сборке. Платёжный срез не объявляется выручкой или полным оборотом. Люди, компании, группы и связи остаются обезличенными.
- В библиотеке 9 банковских PDF и OCR 64 страниц. Сохранены файл, SHA-256, ссылка, страница и дата. Обзор стали относится к 2021 году. Для золотого обзора известен месяц, точный день остаётся `null`.
- OCR не равен полной разметке Document/Claim/Relation/Issue из методологии команды. Три выбранных тезиса по ставке имеют структурированную атрибуцию. Полная ручная разметка корпуса и независимая проверка всех тезисов не выполнены. Статус `human_verified` автоматически не присваивается.
- Банк, цитирующий ЦБ, не становится владельцем позиции ЦБ. Прогноз сохраняет свою дату и горизонт. Модельная интерпретация и фактический финансовый эффект компании различаются.
- Открытый поиск — пять ограниченных каналов, а не полный охват СМИ. Ранжирование — собственные прозрачные правила, не обученная персональная модель. Фильтруются дата/применимость/дубликаты; учитываются роль, известные признаки профиля, источник и чтение текста. Балл не означает вероятность или денежный эффект. Отзывы сохраняются для оценки качества, они не объявляются обучением модели. Поисковый заголовок не подтверждает новость; недоступная страница не заменяется знаниями модели.
- Дневной бюджет организаторов: 500 рублей на общий ключ команды, сброс в 03:00 МСК. Стоимость конкретного запроса и остаток бюджета не оцениваются без тарифа/API баланса. Неоднозначный результат платного запроса после сбоя не повторяется молча.
- Render Free теряет новые файлы и историю после простоя/перезапуска. Исходные примеры восстанавливаются. Подпись сессии стабильна при неизменных секретах: личное пустое пространство можно восстановить из подписанной сессии, потерянные документы — нельзя. Важные результаты скачивайте.

## Архитектура

Собственный Python-контроллер, без OpenClaw, LangChain, LangGraph или готового agent runtime:

| Компонент | Назначение |
|---|---|
| `identity.py`, `access.py` | Сотрудник, принадлежность компаний, подписанная HttpOnly-сессия с отдельным серверным секретом |
| `workspace.py`, `ingestion.py`, `document_parser.py` | Привязанные загрузки, bounded parsing/OCR, профиль и неизменяемые снимки |
| `case_data.py` | Проверка SHA и индекс трёх CSV на чтение |
| `bank_library.py`, `data/bank_library.json` | Поиск фрагментов девяти PDF с датами/страницами |
| `research.py` | План → инструменты → интерпретация → проверка → изменение плана/уточнение/публикация |
| `public_sources.py` | HTTPS-поиск/чтение с ограничениями, блокировкой внутренних адресов и фиксацией проверенного IP при TLS-подключении |
| `news.py`, `news_sources.py`, `news_ranking.py` | Неплатная очередь сбора, пять публичных каналов, даты/копии/чтение, приоритет под профиль и роль, изолированные подборки и отзывы |
| `engine.py`, `role_rules.py`, `verification.py` | Сохранённый расчётный сценарий ставки с Decimal и правилами применимости |
| `gateway.py`, `prompts/` | Только API и шесть разрешённых моделей организаторов, лимиты/контракты/учёт попыток |
| `api.py`, `static/`, `worker.py` | Четыре раздела интерфейса, API и один фоновый worker |

Исследование использует отдельное состояние `research_jobs`; расчётные разборы остаются в `runs`. Статусы: QUEUED, RUNNING, WAITING_INPUT, SUCCEEDED, PARTIAL, FAILED, CANCELLED, DEFERRED_BUDGET. Состояния, снимки, попытки API, источники и краткие основания переходов сохраняются в SQLite. Права и лимиты проверяет Python; модель не выбирает tenant, SQL, команды или секреты.

Расчётный сценарий — `qwen/qwen3.6-35b-a3b`; извлечение профиля и исследование — `z-ai/glm-5.3-flash`; OCR сканов — `qwen/qwen3-vl-30b-a3b-instruct`. Все входят в список организаторов. Настройка модели не разрешает выход из списка. Планирование и проверка — отдельные вызовы; это автоматическая проверка согласованности, не независимая экспертиза истинности источников.

Если текст файла прочитан, но ответ извлечения дважды нарушил контракт, исходный текст остаётся доступным с явным предупреждением. Непроверенные структурированные значения не принимаются. Ошибка транспорта, авторизации или общего бюджета этим режимом не маскируется.

Исследование использует ограниченный каталог командных механизмов: банковские ALM/ликвидность/кредитный риск, корпоративное финансирование, денежный цикл, спрос, затраты, валюта, конкуренция и регулирование. Модель выбирает применимые механизмы и основания; код формирует условные формулировки и ролевые действия. Это управляемый прототип, а не универсальный отраслевой ресерч или произвольная финансовая модель.

Лимиты исследования: 12 вызовов модели, 8 инструментов, 2 изменения плана после проверки, 300 секунд активного выполнения. Одновременно выполняется одна платная задача. Очередь ограничена. Планы и наблюдения сохраняются как короткие объяснения, скрытые рассуждения не запрашиваются.

## Запуск

Python 3.12, зависимости зафиксированы в `uv.lock` и `requirements.lock`:

```sh
uv sync --frozen
uv run alfa-agent serve
```

По умолчанию: http://127.0.0.1:8765. Ключ задаётся через `ALFA_LLM_API_KEY` или `.env.local` с правами 0600. Для локальной проверки нового релиза можно задать отдельные `ALFA_STATE_DIR` и `PORT`; один worker на папку состояния. `Запустить агента.command` остаётся локальной точкой запуска.

```sh
docker compose up --build
```

Docker/Compose-конфигурация предоставлена; состояние монтируется отдельно. Проверенный Linux-путь — нативная сборка Render; факт локальной Docker-сборки указан отдельно в отчёте проверки и не подменяется наличием Dockerfile.

| Переменная | Значение |
|---|---|
| `ALFA_LLM_API_KEY` | Секрет организаторов |
| `ALFA_ACCESS_PASSWORD` | Общий готовый пароль демо; обязателен для публичного размещения |
| `ALFA_SESSION_SECRET` | Отдельный серверный секрет от 32 символов; обязателен на публичном хосте |
| `ALFA_STATE_DIR` | Папка SQLite/загрузок; на Free временная |
| `ALFA_LLM_MODEL`, `ALFA_RESEARCH_MODEL` | Только разрешённые model ID |
| `PORT`, `ALFA_PUBLIC_DEPLOYMENT` | Порт и публичный режим |

Полные значения секретов не включаются в Git, браузер, отчёты или промпты. `.env*`, `render-access.txt`, `var/` и `reports/` игнорируются. Общий пароль команды сам по себе не позволяет подписать сессию другого сотрудника.

## Проверка

```sh
uv run pytest -q
uv run ruff check src tests
node --check src/alfa_agent/static/app.js
```

Протокольные тесты используют явно выделенные тестовые ответы, не выдают их за работу живой LLM. Живые прогоны и браузерная проверка описаны в `validation-report-v3.json`; локальные подробные отчёты и снимки — `reports/v3/`, в Git они не попадают. [Аудит](docs/CASE_COMPLIANCE_REVIEW.md) перечисляет выполненные условия, частичное покрытие и оставшиеся конкурсные проверки.

Для финальной сдачи нужно зафиксировать точную версию и проверить доступ жюри `alfa-hack-2026` к приватному репозиторию. Полнота конкурсного решения не объявляется доказанной по одному успешному сценарию.
