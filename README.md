# Пульс бизнеса

Персональная новостная аналитика для руководителей крупного бизнеса. Система связывает **новость → контекст компании → материалы Альфа-Банка → возможные последствия и действия для конкретной роли**.

Прототип для кейса «Новостная аналитика для принятия бизнес-решений» хакатона Альфа-Банка.

**[Открыть демо](https://alfa-business-pulse.onrender.com)** · [Требования кейса](docs/CASE_COMPLIANCE_REVIEW.md) · [Источники](docs/SOURCE_REGISTER.md) · [Развёртывание](DEPLOYMENT.md)

## Вход и первый сценарий

Тестовый вход: **логин `We2B`, пароль `alfa-case`**. Это общее демонстрационное пространство; используйте вымышленные данные. Для личного пространства зарегистрируйтесь с кодом команды, затем входите по своему логину и паролю. Название работодателя и должность не подтверждают принадлежность к организации.

1. Выберите компанию и роль: **CFO, казначей, CEO, COO, CCO или CMO**. Можно создать свою компанию.
2. В «Моей компании» загрузите документы или расскажите о бизнесе помощнику. Проверьте предложенные сведения и подтвердите их: черновик не влияет на аналитику.
3. На главной посмотрите сводку важных новостей или задайте вопрос в строке поиска.
4. Запустите исследование, выберите период новостей и горизонт планирования. Проверьте основания, условия применимости, пробелы и следующий шаг для вашей роли.
5. Сохраните новость или отчёт в избранное, скачайте Markdown/JSON либо задайте уточнение с исходным или актуальным контекстом компании.

## Возможности

| Раздел | Что можно сделать |
|---|---|
| Обзор | Увидеть важные новости, даты, источники и объяснение приоритета; найти новости, материалы банка и фрагменты своих документов одной строкой |
| Моя компания | Загрузить файлы, пройти AI-интервью, проверить и отредактировать профиль, исключить материал из новых исследований |
| Исследования | Поставить свой вопрос, увидеть этапы работы агента, получить вывод, сценарии, ограничения и действия с привязкой к источникам |
| Избранное и отчёты | Сохранить новости и исследования, вернуться к истории, продолжить анализ и экспортировать результат |

Поиск свежих новостей использует публичные RSS и новостную выдачу, проверяет даты, объединяет копии и ранжирует события по компании и роли. Балл — приоритет проверки, а не вероятность или денежный эффект. Недоступные источники и непрочитанные заголовки обозначаются явно.

Загруженные документы обрабатываются с сохранением цитат и локаторов. Исключённые файлы не участвуют в новом анализе; старый отчёт сохраняет свой снимок контекста. Внутренний вопрос и документы не передаются в публичный поиск.

### Сценарии для CFO и казначея

В профиле можно подтвердить условия одного договора: тип ставки, остаток, валюту, бенчмарк, переоценку, погашение и срок фиксации. Три синтетических примера создаются как отдельные компании.

- **Плавающий долг:** чувствительность процентных расходов к условному изменению договорной ставки на −1 / 0 / +1 п.п. с учётом переоценки и погашения. Расчёт доступен только при достаточных подтверждённых условиях.
- **Фиксированный долг:** рыночный стресс не меняет ставку действующего договора в подтверждённом защищённом периоде; рефинансирование рассматривается отдельно.
- **Условия неизвестны:** численный эффект не выдаётся, система перечисляет недостающие данные.

CFO получает вопросы к бюджету процентных расходов, казначей — к платёжному календарю и срокам фондирования. Метод: простой процент ACT/365 при постоянном остатке без хеджа. Это условная чувствительность, а не фактический эффект новости или чистая прибыль. Для банка корпоративная формула блокируется: нужна ALM-модель активов и обязательств.

## Как работает агент

**План → инструменты → сохранение оснований → проверка применимости → аналитика → проверка → результат, пересмотр плана или запрос данных.**

Собственный Python-контроллер управляет инструментами компании, банковской библиотеки, публичного поиска и чтения страниц. LLM планирует и выбирает основания; сервер проверяет доступ, аргументы, цитаты, даты, числа и лимиты. Финансовые расчёты выполняются кодом. Инструкции внутри загруженных материалов считаются данными.

Материалы банка сохраняют исходную дату и тип утверждения: факт источника, оценка, прогноз или сценарий. Прогноз не становится фактом, пауза по ставке — новым удорожанием, розничная депозитная ставка — условиями корпоративного кредита. При нехватке оснований результат остаётся частичным (`PARTIAL`).

**Стек:** Python, FastAPI, Pydantic, PostgreSQL, SQLite/FTS5, HTTPX, HTML/CSS/JavaScript. API обслуживает интерфейс, отдельный worker выполняет задачи. PostgreSQL хранит рабочее состояние и оригиналы файлов; SQLite используется локально и для поискового индекса кейса.

**ИИ:** только API организаторов `https://changellenge.up.railway.app/v1` и шесть разрешённых моделей. По умолчанию: `z-ai/glm-5.3-flash` для исследований/профиля, `qwen/qwen3.6-35b-a3b` для расчётного сценария, `qwen/qwen3-vl-30b-a3b-instruct` для сканов. OpenClaw и готовые агентские системы не используются. Общий лимит ключа — 500 руб./день, сброс в 03:00 МСК; живые вызовы расходуют бюджет.

## Данные и ограничения

- В репозитории находятся CSV кейса, индекс девяти банковских PDF, структурированные банковские тезисы и явно синтетические примеры. Происхождение и права компонентов — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
- Платежи не объявляются выручкой, наличие кредита — его остатком или типом ставки. Неизвестные условия не заменяются нулём.
- Контекст и необходимые фрагменты файлов передаются моделям через API организаторов. Ключ остаётся на сервере. Частные материалы доступны по правам пользователя и компании; профессиональная роль не повышает доступ.
- Независимая финансовая экспертиза и измерение полноты поиска не завершены. Автопроверки не гарантируют истинность каждого вывода; экспертное подтверждение не присваивается автоматически.
- Банковская SSO, реальные счета и операции не подключены. Render Free имеет холодный старт и ограниченные ресурсы; бесплатная PostgreSQL действует до **24 ноября 2026 года**.

Первичный регламент — [ТЗ](docs/source-materials/case.pdf). Дополнительный контекст: [методология разметки](docs/source-materials/labeling-methodology.pdf), [анализ аудитории](docs/source-materials/audience-analysis.docx), [Miro](https://miro.com/app/board/uXjVEY6IJiQ=/?share_link_id=975023695519).

## Локальный запуск

Нужны Git, Python 3.12 и `uv` либо Docker Compose. Для живой аналитики нужен ключ организаторов; данные кейса включены в репозиторий.

```sh
git clone https://github.com/andreiczh/alfa-news-analytics.git
cd alfa-news-analytics
cp .env.example .env.local
```

Заполните `.env.local` собственными значениями без пробелов и shell-символов в секретах:

```dotenv
ALFA_LLM_API_KEY=REPLACE_WITH_ORGANIZER_KEY
ALFA_ACCESS_PASSWORD=REPLACE_WITH_REGISTRATION_CODE
ALFA_SESSION_SECRET=REPLACE_WITH_RANDOM_SESSION_SECRET
ALFA_AUTH_MODE=accounts
ALFA_REQUIRE_WORKER=1
```

`ALFA_ACCESS_PASSWORD` — код регистрации, минимум 16 символов; `ALFA_SESSION_SECRET` — отдельный случайный секрет, минимум 32 символа. Файл не включается в Git. Тестовый облачный аккаунт автоматически в локальной базе не создаётся.

**Нативно, macOS/Linux** (Windows — WSL2):

```sh
chmod 600 .env.local
uv sync --frozen
set -a
. ./.env.local
set +a
uv run alfa-agent build-case-index
uv run alfa-agent serve
```

**Или Docker:**

```sh
docker compose up --build
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765) и зарегистрируйтесь с заданным кодом. API и worker запускаются вместе; Compose сохраняет локальные данные в volume `agent-state`. Остановка — `Ctrl+C`, для Compose — `docker compose down`.

Для PostgreSQL задайте `ALFA_DATABASE_URL`; без него локально используется SQLite. `ALFA_STATE_DIR` меняет каталог состояния, `PORT` — порт. Публичное HTTPS-размещение и резервное копирование описаны в [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверка и материалы сдачи

```sh
uv run --frozen pytest -q
uv run --frozen ruff check src tests scripts
```

Бесплатные тесты используют контролируемые ответы; живой API и доступность издателей проверяются отдельно. Зависимости зафиксированы в `uv.lock` и `requirements.lock`; запуск контейнеров — в `Dockerfile` и `compose.yaml`.

Для сквозной демонстрации создайте синтетическую компанию с плавающим долгом, выберите свежую прочитанную публикацию о ставке и сравните CFO/казначея. Повторите с фиксированными и неизвестными условиями: выводы и допустимость чисел должны различаться. Для загрузки доступны [тестовые документы](data/test_documents/). CSV можно проверить на обезличенной компании `U_100110`, не пытаясь восстановить её название.

Подробная проверка конкурсных требований — в [CASE_COMPLIANCE_REVIEW.md](docs/CASE_COMPLIANCE_REVIEW.md). Перед сдачей проверьте доступ жюри и конкурсный коммит, проведите ручную проверку банковских тезисов и выводов.
